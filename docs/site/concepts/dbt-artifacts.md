# dbt Artifacts

dbt generates several artifact files during compilation and execution. dbt-tools reads these files to produce operational intelligence without requiring a live dbt process or database connection.

## Key Artifacts

### manifest.json

Generated by `dbt compile` or `dbt run`. Contains the full graph of nodes in your dbt project:

- **Models** — SQL models with their dependencies, configurations, and metadata
- **Sources** — external data source definitions
- **Tests** — data quality tests and their relationships to models
- **Exposures** — downstream consumers of dbt models

### run_results.json

Generated by `dbt run`, `dbt test`, and other execution commands. Contains the results of the most recent invocation:

- Node execution status (success, error, skipped)
- Timing information
- Adapter response metadata
- Error messages for failed nodes

### catalog.json

Generated by `dbt docs generate`. Contains column-level metadata for models and sources, including data types and row counts.

## Artifact Locations

By default, dbt writes artifacts to the `target/` directory of your dbt project:

```
my-dbt-project/
└─ target/
   ├─ manifest.json
   ├─ run_results.json
   └─ catalog.json
```

## Working with Artifacts Safely

dbt artifacts may contain sensitive information depending on how your project is configured:

- Model SQL may reference internal schema or table names
- Metadata may include warehouse connection details in some configurations
- Test results may surface data quality failures that reveal schema information

dbt-tools reads these artifacts locally and does not transmit them externally. When sharing artifact-derived outputs (reports, screenshots, examples), use synthetic project names and schemas.
